# BudBot local preview

## Start the demo

1. Open the repository's `launchers` folder in your file browser.
2. Double-click **BudBot Control Center** (Linux Mint) or **Launch BudBot Control Center.vbs** (Windows).
3. Click **Start BudBot** and wait for the status to show **Running**. The selected customer's widget preview opens in your browser.
4. Use **Open BudBot** any time to open the preview again. No UUID or terminal command is needed.

On Linux Mint, if the desktop does not run the launcher the first time, right-click **BudBot Control Center.desktop**, select **Allow Launching**, then double-click it. Linux requires Docker Engine, Docker Compose V2, Python 3, and Tkinter (`python3-tk`). Windows requires Python 3 with Tcl/Tk and Docker Desktop with Compose V2. Keep the Docker service/Desktop running while BudBot is in use.

The Control Center lets you choose among active local businesses and edit its business name, logo, assistant name, greeting, brand color, and optional assistant avatar. The business logo appears in the widget header and is also the default circular assistant avatar beside chat messages. There is only one business-logo upload; the optional assistant avatar overrides it for chat messages only. Removing that override returns chat messages to the business logo, or the assistant's letter fallback when no logo is set. PNG, JPG, and WebP images are checked by BudBot, limited to 4 MB and 16 megapixels, and saved in the persistent `budbot_local_assets` Docker volume. **Restore Defaults** clears the business logo, assistant avatar, and business brand color; it preserves the names, greeting, and existing assistant/location overrides.

## Safe local operation

The backend and PostgreSQL ports are bound to localhost. Control Center branding and business-picker routes exist only in development, reject non-local Host/Origin requests, and require M9A authenticated membership/permissions (plus CSRF for writes). The business-ID header never authorizes administration. The separate `/admin/` dashboard uses the normal authenticated branding endpoint; customer image delivery publishes only the current logo/avatar references. Do not expose these services to a LAN or publish this development preview. Stop and Restart preserve the PostgreSQL and uploaded-asset volumes; existing `.env` is never overwritten.

The demo works without an AI provider or paid API key. Deterministic commands such as `/help`, `/hours`, `/locations`, and `/about` remain available. Natural-language answers require an operator-configured AI provider. Configure provider credentials privately in `.env`; never put credentials in the widget or browser.

## Embed source

The local preview loads the embeddable custom element from `/widget/src/embed.js`. On a customer site, include it after configuring the backend's public deployment and authentication in a later milestone:

```html
<script type="module" src="https://your-budbot-host/widget/src/embed.js"
        data-business-id="YOUR-BUSINESS-UUID"></script>
```

The widget displays the business logo in its header and uses that same saved logo reference for the circular assistant avatar unless an optional assistant avatar is configured. It preserves the image's aspect ratio in the header and uses circular cropping for message avatars. It only loads image references generated by BudBot's same-origin image store; arbitrary remote image URLs are ignored. Legacy saved local references and new published references use `/assets/branding/` for customer delivery. Image fetches omit admin cookies and render through Blob URLs, so an embedding page's image CSP must permit `blob:` alongside its existing widget API policy.
